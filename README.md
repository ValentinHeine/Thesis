# Chunk-Based Data-Parallel Parsing of XML Streams: thesis artifacts

Source code and experiment data for the bachelor thesis *Chunk-Based Data-Parallel Parsing of XML
Streams* (Valentin Heine, TU Berlin, DIMA, 2026; advisor Aljoscha Lepping).

The implementation is an XML input formatter for [NebulaStream](https://github.com/nebulastream/nebulastream).
This repository contains only the changes on top of NebulaStream, in two equivalent forms.

| Path | Contents |
| --- | --- |
| `nebulastream-changes/xml-formatter.patch` | All thesis changes as one `git` patch (41 files) |
| `nebulastream-changes/files/` | The same changed and added files, at their NebulaStream paths |
| `experiments/` | Measured data behind every figure of Chapter 5/6, plot script, dataset checksums |

## Base version and applying the patch

The patch applies to NebulaStream commit `d180ec6e0fe128ab15cc87adfaedd48ea03a24a1` (16 Jun 2026).

```bash
git clone https://github.com/nebulastream/nebulastream.git
cd nebulastream
git checkout d180ec6e0fe128ab15cc87adfaedd48ea03a24a1
git apply /path/to/xml-thesis-artifacts/nebulastream-changes/xml-formatter.patch
```

Build NebulaStream as described in its own documentation (development container toolchain).

## Running the tests

```bash
# unit tests: XML, CSV and JSON formatter on small files, buffers down to 16 bytes
ninja input-formatter-test-small-files && ./nes-input-formatters/tests/UnitTests/input-formatter-test-small-files
```

`DISABLED_testMultilineCommentsXML` is disabled on purpose: it feeds newline-framed XML whose comment
contains a newline, which violates the framing contract. RapidXML then throws on a worker thread and
the process aborts. The same data with the Record Separator delimiter
(`testMultilineCommentsWithRecordSeparatorXML`, 16-byte buffers) passes. See thesis §4.2 and §6.1.

## Experiments

Detailed methodology, invocations and caveats are in
`nebulastream-changes/files/nes-input-formatters/benchmark/results/README.md` and
`.../benchmark/simd-prototype/README.md`. Summary:

| Thesis figure / table | Data | Produced by |
| --- | --- | --- |
| Worker scaling (Fig. 5.x) | `experiments/evaluation_workers.csv` | `systest -b … Bimbo_XML.test` / `Bimbo_CSV.test` with 1–16 worker threads; `xml-sax-baseline --preset bimbo --runs 5` |
| Hardware counters 4/8/16 workers | `experiments/worker_scaling_counters.csv` | `perf stat` (instructions, cycles, cache-references, cache-misses) on the same query, 3 reps; aggregated values only, raw `perf` output was not kept |
| Source scaling (Fig. 5.x) | `experiments/evaluation_sources.csv` | 1–32 File+XML sources, 8 workers; raw log `benchmark/results/raw/ms2_sources_190MB_2026-07-24.txt` |
| Profile, copy experiment, SIMD prototype (Ch. 6) | `experiments/simd_prototype.csv` | `bench_simd.cpp`, `bench_parsecopy.cpp` (checksum-gated microbenchmarks) |

Plots: `experiments/plots/plot.py` renders the figure SVGs from the CSV files; `build.sh` converts SVGs to the PDFs used in the thesis.

Correctness cross-check: on `Bimbo_500MB.xml`, NebulaStream (`Bimbo_XML.test`, Checksum sink) and the
independent Expat baseline both produce `1373000 2895024047` (tuple count, byte-sum checksum).

### Datasets

The large inputs (1.7 GB) are not included. `experiments/datasets.sha256` lists their SHA-256 sums.
`Bimbo_500MB.xml` was generated by tiling `nes-input-formatters/tests/UnitTests/testdata/XML/Bimbo.xml`
with upper-cased field tags (see the header of `Bimbo_XML.test`). Files can be provided on request.

Machine: 16-thread development container, idle during runs; NebulaStream in `COMPILER` execution mode.
